# Procedural maps

The [Dungeon Foundry](../Web/wwwroot/dungeon-generator.html) authors standalone generated dungeons. The map preview and the **Generate** and **Play** actions stay visible while you work. Desktop users have a settings sidebar; on phones, **Settings** opens a dialog. Changing layout settings marks them as pending: **Generate** (or **Generate dungeon** in the phone dialog) applies them. **Play** always opens the map currently shown. Art style, environment tiles, and room material variation update the displayed map immediately.

Choose connected chambers, natural caverns, or grand halls. **Advanced settings** contains the seed, board size (6×6 to 20×16), target room count (2–6), landmark density, and playable terrain. Small boards may fit fewer rooms than requested. By default Generate uses a fresh seed; enable **Keep this seed fixed** to reproduce the same layout and settings, or use the reroll button to choose a fresh seed. Typing a seed enables fixed-seed mode. Failed generation keeps the current map.

## Preview and themes

The live preview uses the native Book Location Tiles library. Choose Pocket Dungeon, Ink & Lanterns, or Dungeon After Dark, then select one of 31 environment kits. Inspect the map in square art mode or blueprint. The tile grid is orthogonal with 128×128 logical cells. The preview uses square floors, frontal doors, and props and landmarks from the selected kit; it does not mix pieces from related kits. Floor choices come from the kit's eligible full-ground assets, selected using their edge tags rather than a fixed first-four palette. A seeded connector graph uses supplied transition floors to identify reachable room materials; the fitter still has to prove the whole floor arrangement works. Each room gets a seeded material preference, with small coherent two-cell wear patches when **Vary room materials** is on. Cells on the protected route, including the entrance and exit, keep the shared base material. Turn variation off for a uniform floor. The renderer composites floors at their native integer resolution before applying zoom so neighboring cells remain seamless. Environment ambiance changes the preview backdrop and glow, not the art pixels. Material and atmosphere choices are preview metadata; **Terrain & hazards** selects the canonical Stone stronghold, Forgotten sewer, or Ancient crypt rules for game export.

The map reserves connected, walkable positions for the entrance, party, enemies, and exit before adding decoration. The entrance and exit are interior portals; the outer boundary stays blocked. The entrance door is selected by its `portal.open` tag and rotated toward its legal route approach. The exit uses stairs art; both portals are visibly labeled, and the route overlay shows the connected path. The exit is placed at the graph-distant reachable cell and excluded from party spawns. Decorations cannot block those reserved positions or disconnect the dry route.

The selected environment kit supplies decorative landmarks. A **Blocked object** outline marks a movement-blocking decoration from the canonical playable map at its actual cell and footprint; that collision comes from canonical map data, not from the selected book-art prop. W, O, and F markers and counts show playable water, oil, and fire tags from the exported map. A wet-looking illustrated floor alone is decorative and is not a hazard. Rotate the whole map in 90-degree steps. Zoom with the controls, mouse wheel, or `+` and `−`; drag to pan while zoomed, use arrow keys to pan, and press Home or **Fit map** to reset. Map details opens the entrance/exit, route, terrain, and room-material information in a dialog.

Foundry checks the square floor tiles against neighboring floors and wall boundaries. Already compatible layouts keep their chosen tiles; when a seam needs correction, a deterministic bounded search can change floor variants and quarter-turn rotations while preferring the original arrangement. It can also select a compatible wall from same-layout candidates, preferring the authored wall where possible. If it cannot find a fit within its search budget, generation reports the fitting error and keeps the current map. To inspect the result, open **Map details → Tile edge tags → Inspect connections on the map**. The overlay marks matching joins and mismatches; click a floor tile or use map focus with arrow keys and Enter, then Escape to close the overlay. The details dialog shows the actual placed tile and its connections. The separate catalog selector inspects a library component without changing the map. These tags and visual adjustments do not change the canonical layout, collision, hazards, or gameplay rules; manual joins require review and are excluded from automatic floor fitting. Tags only select among supplied art and cannot create missing transition assets, and this work does not alter art manifests. See [Tile edge tags](Tile-Edges.md) for the authored format and limits.

## Edit, export, and play

The **Export** dialog offers the room workshop, recipe JSON, playable JSON, and a PNG snapshot. The recipe preserves the seed, generated layout, and visual settings. Playable JSON uses the canonical map schema and terrain/collision data, with optional native-art presentation metadata for the chosen style, kit, and exact floor, wall, door, and prop composition. The browser runtime renders gameplay on square tiles. Play is disabled until the selected art loads, so it cannot launch a stale visual composition. If art loading or map validation fails, the current generated map and saved run remain intact.

**Play** asks whether to explore freely before combat; the checkbox is on by default. Confirming replaces the active browser save with a new standalone run, so export the current save first if you want to keep it. In exploration, move one cardinal step at a time with WASD, arrow keys, or the direction pad. Approaching an enemy within three walkable steps starts the usual turn-based tactical battle, with the party deployed near its exploration position. After victory, choose the sponsor reward if offered and continue to clear the encounter; then walk to the exit and press E or Space (or use the interaction button) to finish the dungeon. If you turn off free exploration, Play starts directly in the tactical battle. Defeating all enemies remains the battle win condition. Invalid playable JSON is rejected without replacing the current run. Generated maps remain standalone and do not enter campaign progression.

The generator is browser authoring JavaScript. The shared C# runtime validates and persists optional native visual metadata for custom maps; the browser renderer uses orthogonal square tiles for gameplay maps, including authored maps whose walls are drawn from canonical wall data. This presentation does not convert a map into the procedural campaign or alter its canonical layout, collision, or hazards. Style, kit, and floor-variety settings remain in the editable recipe; exported playable JSON carries the specific rendered pieces and style/kit identifiers. No Unity scene or Unity Tile integration is implied by the preview.

The preview also inspects authored tile-edge tags and validates neighboring full-floor seams before export or Play. See [Tile edge tags](Tile-Edges.md) for the format, manual-review and overlay markers, and library workflow.

## Reproducibility and implementation

Keep the seed, layout, gameplay biome, art style, environment theme, dimensions, density, and requested room count with a recipe. Preview rotation does not change the generated layout. Changes to the generator or its asset library can affect later regeneration; keep the recipe and playable JSON when an exact authored result matters.

Playable biome material and themes are authored in `Web/wwwroot/assets/map-generation-rules.json`. Deterministic layout generation and the canonical playable-map adapter are in `Web/wwwroot/procedural-map.js`; native tile loading and preview rendering are in `Web/wwwroot/generator-art.js` and `Web/wwwroot/dungeon-generator.js`.
