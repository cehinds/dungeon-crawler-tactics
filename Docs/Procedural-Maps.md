# Procedural maps

The [Dungeon Foundry](../Web/wwwroot/dungeon-generator.html) is a browser tool for authoring and playing standalone encounters. The map preview and the **Generate** and **Play** actions stay visible while you work. Desktop users have a settings sidebar; on phones, **Settings** opens a dialog. Changing layout settings marks them as pending: **Generate** (or **Generate dungeon** in the phone dialog) applies them. **Play** always opens the map currently shown. Art style, environment tiles, and room material variation update the displayed map immediately.

Choose connected chambers, natural caverns, or grand halls. **Advanced settings** contains the seed, board size (6×6 to 20×16), target room count (2–6), landmark density, and playable terrain. Small boards may fit fewer rooms than requested. By default Generate uses a fresh seed; enable **Keep this seed fixed** to reproduce the same layout and settings, or use the reroll button to choose a fresh seed. Typing a seed enables fixed-seed mode. Failed generation keeps the current map.

## Preview and themes

The live preview uses the native Book Location Tiles library. Choose Pocket Dungeon, Ink & Lanterns, or Dungeon After Dark, then select one of 31 environment kits. Inspect the map in square art mode or blueprint. The tile grid is orthogonal with 128×128 logical cells. The preview uses square floors, frontal doors, and props and landmarks from the selected kit; it does not mix pieces from related kits. Each room uses one of floor cells 0–3 as its base, with small coherent two-cell wear patches when **Vary room materials** is on. Turn it off for a uniform floor. The renderer composites floors at their native integer resolution before applying zoom so neighboring cells remain seamless. Environment ambiance changes the preview backdrop and glow, not the art pixels. Material and atmosphere choices are preview metadata; **Terrain & hazards** selects the canonical Stone stronghold, Forgotten sewer, or Ancient crypt rules for game export.

The map reserves connected, walkable positions for the entrance, party, enemies, and exit before adding decoration. The entrance and exit are interior portals; the outer boundary stays blocked. The entrance uses open-door art and the exit uses open-door and stairs art; both are visibly labeled, and the route overlay shows the connected path. The exit is placed at the graph-distant reachable cell and excluded from party spawns. Decorations cannot block those reserved positions or disconnect the dry route.

The selected environment kit supplies decorative landmarks. A **Blocked object** outline marks a movement-blocking decoration from the canonical playable map at its actual cell and footprint; that collision comes from canonical map data, not from the selected book-art prop. W, O, and F markers and counts show playable water, oil, and fire tags from the exported map. A wet-looking illustrated floor alone is decorative and is not a hazard. Rotate the whole map in 90-degree steps. Zoom with the controls, mouse wheel, or `+` and `−`; drag to pan while zoomed, use arrow keys to pan, and press Home or **Fit map** to reset. Map details opens the entrance/exit, route, terrain, and room-material information in a dialog.

## Edit, export, and play

The **Export** dialog offers the room workshop, recipe JSON, playable JSON, and a PNG snapshot. The recipe preserves the seed, generated layout, and visual settings. Playable JSON uses the canonical map schema and terrain/collision data, with optional native-art presentation metadata for the chosen style, kit, and exact floor, wall, door, and prop composition. The browser runtime can render that same square art after Play; the metadata does not change movement, hazards, terrain rules, or campaign maps. Play is disabled until the selected art loads, so it cannot launch a stale visual composition. If art loading or map validation fails, the current generated map and saved run remain intact.

Starting a map launches a standalone encounter and replaces the active run, so export the current campaign save first if you want to keep it. Play asks for confirmation and explains this effect. The existing win condition remains defeating all enemies. The exit is a connected route endpoint shown in the preview, not an extraction objective or a new way to complete combat. Invalid playable JSON is rejected without replacing the current run. Generated maps do not enter campaign progression.

The generator is browser authoring JavaScript. The shared C# runtime validates and persists optional native visual metadata for custom maps; the browser renderer uses the same orthogonal projection and piece positions as the preview. Older custom maps without this metadata keep their existing isometric presentation. The art metadata is presentation-only: canonical game tiles continue to decide collision and hazards. Style, kit, and floor-variety settings remain in the editable recipe; exported playable JSON carries the specific rendered pieces and style/kit identifiers. No Unity scene or Unity Tile integration is implied by the preview.

## Reproducibility and implementation

Keep the seed, layout, gameplay biome, art style, environment theme, dimensions, density, and requested room count with a recipe. Preview rotation does not change the generated layout. Changes to the generator or its asset library can affect later regeneration; keep the recipe and playable JSON when an exact authored result matters.

Playable biome material and themes are authored in `Web/wwwroot/assets/map-generation-rules.json`. Deterministic layout generation and the canonical playable-map adapter are in `Web/wwwroot/procedural-map.js`; native tile loading and preview rendering are in `Web/wwwroot/generator-art.js` and `Web/wwwroot/dungeon-generator.js`.
