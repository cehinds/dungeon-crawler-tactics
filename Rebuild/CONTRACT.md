# Rebuild contract
All public JSON uses camelCase public fields; serializer IncludeFields=true. Namespace DccRebuild.
Bridge Initialize(string contentJson, int seed), Dispatch(string commandJson), GetSave(), LoadSave(string).
Command fields: type, direction, targetId, actorId, skillId, itemId, x, y. Types move/interact/select/moveUnit/forecast/confirm/endUnit/endTurn/rest/equip/useItem/retry.
View: mode (explore,battle,defeat,complete), message, seed, turn, selectedId, questStage, gold, party[], inventory[], world, battle, forecast, journal[].
Unit fields id,name,x,y,hp,maxHp,mp,maxMp,level,xp,power,armor,moved,acted,ended,equipment,skills[],ranks dictionary. Inventory entries itemId,count.
World API: static World.Build(int seed) returns WorldMap {width,height,tiles:string[],objects:WorldObject[],spawnX,spawnY}; tiles indexed y*width+x, '#' wall '.' floor. WorldObject {id,kind,name,x,y,description}; kind guide,safe,encounter,boss,exit,chest. Engine stores cleared object IDs. Map must include guide id mordecai, safe id safe-room, encounter ids false-guild/goblin-workshop/hoarder/juicer, boss id ball-of-swine, exit id exit. Story false-guild -> guide -> goblin-workshop -> ball-of-swine -> exit; hoarder/juicer optional after guide. World rendering receives these objects with cleared bool copied in view.
Content root {title,items:[{id,name,kind,power,armor,heal,mp,description}],skills:[{id,name,cost,power,range,element,description}],enemies:[{id,name,hp,power,armor,element}],dialogue:{...}}. Item kind weapon/armor/charm/consumable. Skill IDs punch,powerful-strike,bomb,magic-missile,claw; elements physical,arcane,fire. Enemy fallback values supported. Party fixed Carl and Donut; no classes. Equipment IDs chosen by kind from content. Optional content lore fields retained in authored JSON.
Battle view {width,height,phase,units[],enemies[],obstacles:[{x,y}],encounterId,theme,composition,tiles[],props[]}. Most encounters use a 10 × 8 board. `goblin-workshop` and `ball-of-swine` use the generated industrial-sewer room as their battle board; both currently use an 11 × 8 footprint. `World.BuildArena(seed, encounterId)` returns this room-derived board for those two encounters, translating exploration props to room-relative coordinates and treating every non-floor tile as an obstacle. Forecast {actorId,targetId,skillId,damage,cost,reaction,valid}. moveUnit x/y max Manhattan 3, no crossing obstacles/units. select actorId; forecast targetId/skillId then confirm; endUnit actorId; endTurn. Each unit one move and one action in either order. Enemies then move and attack. Rest and save at safe room; GetSave only allowed adjacent to safe room. Invalid commands return view message, no state change.

World also includes rooms[], optional decorative water ~ (impassable), door and discovery object kinds (inspect descriptions). Root view x/y are exploration position; cleared[] holds completed object IDs. Bare confirm accepts pending forecast. Carl cannot equip weapon kind.

World generation records `generationVersion`. Version 1 is the archived legacy layout; version 2 is the prior concept-room generator and remains available as a migration checkpoint. New seeded worlds use version 3, which shares the industrial-sewer workshop/boss room and arena composition. Save migration accepts supported v1 and v2 checkpoints, regenerates the current v3 world, and preserves validated player progress. Invalid or inconsistent checkpoints are rejected without applying partial state. These generators are compatibility/migration data, not interchangeable descriptions of current generated output.
