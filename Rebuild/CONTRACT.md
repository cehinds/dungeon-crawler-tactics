# Rebuild contract
All public JSON uses camelCase public fields; serializer IncludeFields=true. Namespace DccRebuild.
Bridge Initialize(string contentJson, int seed), Dispatch(string commandJson), GetSave(), LoadSave(string).
Command fields: type, direction, targetId, actorId, skillId, itemId, x, y. Types move/interact/select/moveUnit/forecast/confirm/endUnit/endTurn/rest/equip/useItem/retry.
View: mode (explore,battle,defeat,complete), message, seed, turn, selectedId, questStage, gold, party[], inventory[], world, battle, forecast, journal[].
Unit fields id,name,x,y,hp,maxHp,mp,maxMp,level,xp,power,armor,moved,acted,ended,equipment,skills[],ranks dictionary. Inventory entries itemId,count.
World API: static World.Build(int seed) returns WorldMap {width,height,tiles:string[],objects:WorldObject[],spawnX,spawnY}; tiles indexed y*width+x, '#' wall '.' floor. WorldObject {id,kind,name,x,y,description}; kind guide,safe,encounter,boss,exit,chest. Engine stores cleared object IDs. Map must include guide id mordecai, safe id safe-room, encounter ids false-guild/goblin-workshop/hoarder/juicer, boss id ball-of-swine, exit id exit. Story false-guild -> guide -> goblin-workshop -> ball-of-swine -> exit; hoarder/juicer optional after guide. World rendering receives these objects with cleared bool copied in view.
Content root {title,items:[{id,name,kind,power,armor,heal,mp,description}],skills:[{id,name,cost,power,range,element,description}],enemies:[{id,name,hp,power,armor,element}],dialogue:{...}}. Item kind weapon/armor/charm/consumable. Skill IDs punch,powerful-strike,bomb,magic-missile,claw; elements physical,arcane,fire. Enemy fallback values supported. Party fixed Carl and Donut; no classes. Equipment IDs chosen by kind from content. Optional content lore fields retained in authored JSON.
Battle view {width,height,phase,units[],enemies[],obstacles:[{x,y}],encounterId,theme,composition,tiles[],props[]}. Most encounters use a 10 × 8 board. `goblin-workshop` and `ball-of-swine` use the generated industrial-sewer room as their battle board; both currently use an 18 × 11 footprint. `World.BuildArena(seed, encounterId)` returns this room-derived board for those two encounters, translating exploration props to room-relative coordinates and treating every non-floor tile as an obstacle. Forecast {actorId,targetId,skillId,damage,cost,reaction,valid}. moveUnit x/y max Manhattan 3, no crossing obstacles/units. select actorId; forecast targetId/skillId then confirm; endUnit actorId; endTurn. Each unit one move and one action in either order. Enemies then move and attack. Rest and save at safe room; GetSave only allowed adjacent to safe room. Invalid commands return view message, no state change.

World also includes rooms[], optional decorative water ~ (impassable), door and discovery object kinds (inspect descriptions). Root view x/y are exploration position; cleared[] holds completed object IDs. Bare confirm accepts pending forecast. Carl cannot equip weapon kind.

World generation records `generationVersion`. Version 1 is the archived legacy layout; versions 2 and 3 retain their historical concept grammars as migration checkpoints. Historical v1/v2/v3 maps retain their 60 × 38 dimensions. New seeded worlds use version 4 on a 90 × 52 map with 22 × 16 room sectors, which shares an 18 × 11 inset industrial-sewer workshop/boss room and arena composition, real floor crossings through side water channels, and a northern gate/corridor right of center. Save migration accepts supported v1, v2 and v3 checkpoints, verifies their persisted geometry against the corresponding historical generator, regenerates the current v4 world, and preserves validated player progress. Invalid or inconsistent checkpoints are rejected without applying partial state. These generators are compatibility/migration data, not interchangeable descriptions of current generated output.

Browser architecture overlays are presentation only. Bridge decks cover existing floor crossings between water cells; they never create walkability. Wall faces/caps derive from wall boundaries, and doorway details derive from open corridor boundaries. Props retain their explicit collision footprints. Visual overlap does not override C# tiles, obstacles or movement rules.

Version-4 room rules may specify `tileRows`: exactly `height` strings of exactly `width` characters, using `#`, `.`, and `~`. C# validates and applies this authored footprint before prop placement. The industrial profile reserves a 12 × 6 central area and uses asymmetric three-column water wings with explicit three-cell-long dry crossings. Industrial party/enemy starting cells lie on the enlarged central floor; other encounters retain their existing spawn layout.

`WorldProp.layer == "wallfixture"` identifies art mounted on blocked masonry, including industrial machinery, pipes and gate torches. Version-4 authored placement accepts these fixtures on `#`; validation requires every fixture cell to remain `#`. Solid fixtures retain collision, while nonblocking decorative fixtures may overlap the same masonry. The renderer excludes this layer from the furniture floor-restoration mask and sorts it with foreground scenery, so mounted art cannot turn wall pixels into apparent floor. The northern industrial apron is masonry around the explicit gate opening, with the authored eastern water inset retained.
